# CALIBRATE OS — Claude Code Development Guide

This file is the operating manual for Claude Code when working in this codebase. Follow these rules precisely. They are not suggestions — they reflect deliberate architectural decisions made for this project.

---

## Tech Stack

| Layer | Choice | Notes |
|-------|--------|-------|
| Framework | Next.js 15 (App Router) | All routes use the App Router — no Pages Router |
| Language | TypeScript (strict mode) | No `any` types, ever |
| Database | Supabase (PostgreSQL) | See docs/DATABASE.md |
| Auth | Supabase Auth | Email/password + magic link for MVP |
| Styling | Tailwind CSS v4 | Utility-first, no CSS modules |
| UI Components | shadcn/ui | Copy components into `components/ui/` — do not install as a dependency |
| AI | Anthropic Claude API | claude-sonnet-4-6 for all AI features |
| State | React Server Components + minimal useState | No Redux, no Zustand for MVP |
| Forms | React Hook Form + Zod | Zod schemas are the single source of truth for validation |
| Charts | Recharts | For performance dashboard visualizations |
| Deployment | Vercel | Edge runtime for API routes where appropriate |

## Development Rules

**Never touch these without explicit instruction:**
- `supabase/migrations/` — migrations are append-only, never edit existing migration files
- `types/database.ts` — this file is auto-generated by `supabase gen types typescript`, never hand-edit it
- `.env.local` — environment variables are never committed

**Always do these:**
- Run `npm run typecheck` before considering any task complete
- Use Server Components by default; add `"use client"` only when browser APIs or interactivity require it
- Validate all user input with a Zod schema before it touches the database
- Use the Supabase server client (from `lib/supabase/server.ts`) in Server Components and API routes; use the browser client (from `lib/supabase/client.ts`) only in Client Components

**Never do these:**
- Do not use `fetch` to call your own Next.js API routes from Server Components — call the data function directly
- Do not store sensitive user data in `localStorage` or `sessionStorage`
- Do not call the Anthropic API from the client — only from server-side API routes
- Do not generate AI briefs more than once per user per day — always check `ai_daily_briefs` for an existing record first

## Coding Standards

### File Naming
- Pages: `app/(routes)/page.tsx`
- Layouts: `app/(routes)/layout.tsx`
- Server actions: `app/actions/[domain].ts` (e.g. `checkin.ts`, `training.ts`)
- Components: `components/[domain]/ComponentName.tsx` (PascalCase)
- Utilities: `lib/[domain]/functionName.ts` (camelCase)
- Zod schemas: `lib/schemas/[domain].ts`
- Types: `types/[domain].ts` (hand-authored types only)

### TypeScript
```typescript
// Good — explicit return types on all exported functions
export async function getReadinessScore(userId: string): Promise<number> { ... }

// Bad — implicit return type
export async function getReadinessScore(userId: string) { ... }

// Good — use database-generated types for DB shapes
import type { Tables } from '@/types/database'
type Profile = Tables<'profiles'>

// Bad — hand-writing DB types
type Profile = { id: string; full_name: string; ... }
```

### Supabase Query Pattern
```typescript
// Always destructure error and handle it
const { data, error } = await supabase
  .from('daily_checkins')
  .select('*')
  .eq('user_id', userId)
  .eq('date', today)
  .single()

if (error) throw new Error(`Failed to fetch check-in: ${error.message}`)
```

### Server Actions
```typescript
'use server'
import { z } from 'zod'

const CheckinSchema = z.object({ ... })

export async function submitCheckin(formData: FormData) {
  const parsed = CheckinSchema.safeParse(Object.fromEntries(formData))
  if (!parsed.success) return { error: parsed.error.flatten() }
  // ... proceed with validated data
}
```

### AI Prompt Pattern
All Claude API calls go through `lib/ai/generateBrief.ts`. Never scatter raw Anthropic client calls across the codebase.

```typescript
// lib/ai/generateBrief.ts
import Anthropic from '@anthropic-ai/sdk'

const client = new Anthropic() // reads ANTHROPIC_API_KEY from env

export async function generateDailyBrief(context: BriefContext): Promise<DailyBrief> {
  const message = await client.messages.create({
    model: 'claude-sonnet-4-6',
    max_tokens: 1024,
    messages: [{ role: 'user', content: buildPrompt(context) }],
  })
  // parse and return structured output
}
```

## Architecture Standards

### Route Structure
```
app/
  (auth)/
    login/page.tsx
    signup/page.tsx
  (app)/
    layout.tsx          ← authenticated shell with sidebar
    dashboard/page.tsx
    checkin/page.tsx
    training/page.tsx
    nutrition/page.tsx
    brief/page.tsx
  onboarding/
    page.tsx
  api/
    ai/brief/route.ts   ← AI generation endpoint
```

### Data Fetching
- Fetch data in Server Components using the Supabase server client
- Pass data down as props to Client Components — do not re-fetch in Client Components
- Use Next.js `cache()` for expensive reads that are called multiple times in a single render

### Readiness Score
Readiness score is computed in `lib/performance/readiness.ts` and written to the database on check-in insert. It is never recomputed from stored data — if the formula changes, a migration backfills existing rows.

### AI Brief Generation Flow
1. User completes daily check-in → readiness score computed and saved
2. Server action calls `lib/ai/generateBrief.ts` with user context (profile, readiness score, last 7 days training load, today's nutrition targets)
3. Claude API returns structured brief
4. Brief is saved to `ai_daily_briefs` — one row per user per day
5. If a row already exists for today, skip generation and return cached row

### Environment Variables
```
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=    ← server-only, never expose to client
ANTHROPIC_API_KEY=             ← server-only, never expose to client
```

## UI Standards

### Design Language
CALIBRATE OS uses a **dark, high-contrast performance aesthetic**. Think sports science lab meets premium fitness app. Not clinical white. Not consumer-pastel. Data-forward and serious.

### Color Palette
Use these semantic Tailwind classes — do not hard-code hex values:
- Background: `bg-zinc-950` (primary), `bg-zinc-900` (card/panel)
- Text: `text-white` (primary), `text-zinc-400` (secondary), `text-zinc-600` (muted)
- Accent: `text-emerald-400` / `bg-emerald-400` — the CALIBRATE brand color
- Readiness Green: `text-emerald-400` (score 80–100)
- Readiness Yellow: `text-amber-400` (score 50–79)
- Readiness Red: `text-red-400` (score 0–49)
- Borders: `border-zinc-800`

### Typography
- Font: Inter (system default fallback acceptable for MVP)
- Headings: `text-white font-semibold tracking-tight`
- Body: `text-zinc-400 text-sm leading-relaxed`
- Metrics / numbers: `text-white font-mono font-bold` — numbers are always white and prominent

### Component Conventions
- Cards: `bg-zinc-900 border border-zinc-800 rounded-xl p-6`
- Primary button: `bg-emerald-400 text-zinc-950 font-semibold hover:bg-emerald-300`
- Secondary button: `bg-zinc-800 text-white hover:bg-zinc-700`
- Input fields: `bg-zinc-900 border-zinc-700 text-white placeholder:text-zinc-600 focus:border-emerald-400`

### Readiness Score Display
The readiness score (0–100) is the most important number in the product. It gets:
- Large mono font: `text-6xl font-mono font-bold`
- Color based on range (green/yellow/red above)
- Always accompanied by a label: "READY", "MODERATE", or "RECOVER"

### Forms
- All forms use a single-column layout
- Labels are `text-xs font-semibold uppercase tracking-wider text-zinc-500`
- Inline validation errors appear below the field in `text-red-400 text-xs`
- Submit buttons are full-width on mobile

### Responsive Design
- Mobile-first. All layouts start single-column.
- Dashboard grid: `grid-cols-1 md:grid-cols-2 lg:grid-cols-3`
- Sidebar navigation collapses to bottom tab bar on mobile
- Minimum supported width: 375px (iPhone SE)

### Loading States
- Use React Suspense with skeleton loaders — never blank white screens
- Skeleton elements: `bg-zinc-800 animate-pulse rounded`
- Loading text: never show "Loading..." — show skeleton shapes instead
